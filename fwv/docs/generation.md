# 生成服务

本页介绍 API 模式。工作台的“AI 生图”页提供用户服务配置、文生图、单张参考图编辑和任务结果。角色换皮也支持无需在 FWV 配置 Key 的[本地 Agent 模式](local-agent.md)，由当前 Codex 对话分析并使用内置图像工具执行。两种模式的图片均可进入项目素材库，沿用版本、加工、检查与导出流程。

## 配置

- Base URL 默认为 `https://api.openai.com/v1`，应填写 API 根路径，不含 `/images/generations`。非本机服务要求 HTTPS。
- 模型默认为 `gpt-image-2`，可填写服务商实际提供的模型标识。
- GPT Image 协议发送 `n=1`、PNG 输出、质量和可选背景参数。基础兼容协议发送 `response_format=b64_json`，不发送专属背景参数；它不保证兼容所有平台或旧模型。
- API Key 通过本机服务发送给明确配置的服务商。填写后保存，密码输入框清空。切换 Base URL 会清除旧凭据。

Key 只保留在本机服务内存中，不进入浏览器存储、项目索引、资源配方或导出包。也可以由启动器注入 `FWV_IMAGE_API_KEY`、`FWV_IMAGE_BASE_URL`、`FWV_IMAGE_MODEL`。不会自动复用其他工具的 `OPENAI_API_KEY`。本机 loopback 的兼容服务可以不使用 Key；服务本身如要求鉴权，仍需配置。

“测试连接”请求 `GET /models`，仅证明该接口可访问。列表中有模型也不证明图像权限或余额；有些兼容服务不提供模型列表，但仍可尝试生成。生成是否支持具体尺寸、质量、透明背景，以实际服务返回为准。

## 请求与结果

文生图调用 `POST /images/generations`，有参考图则调用 Multipart `POST /images/edits`。当前每次一张结果、最多两个同时执行的任务，生成请求超时为 180 秒。参考图从登记的不可变版本读取，验证后才发给模型服务。

结果必须为有效的 PNG、JPEG 或 WebP，单张最多 32 MiB。保存实际输出、来源模型、参数、提示词、服务请求编号及服务返回的用量；参考图另存为 `reference` 文件，导出时放入 `references/`。后续图片加工继续保留生成来源、最初生成版本编号及参考图字节。不根据固定单价猜测费用，不把随机生成描述为像素可复现。

客户端定时读取任务状态，不会重新提交生成。任务可能处于：

| 状态 | 含义与操作 |
| --- | --- |
| queued / running | 排队、服务处理中或正在写入项目 |
| succeeded | 已入库，可打开图片工作台 |
| ready | 模型已返回图片，等待入库；界面明确显示“已暂存到磁盘”或“尚未落盘”。“保存已生成图片”只重试本地保存，不调用模型 |
| failed | 已知失败，查看具体参数、鉴权或服务错误 |
| unknown | 远端可能已执行；先核对服务商记录，不自动重新生成 |
| cancelled | 请求在发出前取消 |

取消本地等待不保证取消服务商的执行或计费。请求发出后的网络中断、超时、取消、HTTP 408/5xx 或无法使用的成功响应都保守标记为 `unknown`。FWV 先将请求编号、参数与派发意图记录到项目，再调用服务；同一个项目内相同请求编号及参数跨服务重启仍只创建同一个任务，内容不同会拒绝。无法写入请求记录时不派发。恢复时仍未确认的任务不会自动重新提交。

模型返回有效图片后，先把原始输出、参考图、固定的生成时间和完整来源记录写入 `.fwv/generation/<任务编号>/`，同步文件内容并原子提交 `result.json`，然后才登记资产。参考图与输出均按长度和 SHA-256 校验。服务重启会恢复这些待入库结果；无需重新配置 API Key 即可保存。登记成功后清理临时图片，任务记录继续保留用于查询和去重；任务列表显示最近 100 条并保留所有待入库任务。

资产登记使用项目写锁内的导入回执。同一结果重复保存、资产已登记但响应丢失、任务状态更新失败，以及两个服务同时恢复保存，都会核对原入库版本和真实文件后使用同一资产，不创建重复资产，也不回退用户后来选用的版本。恢复文件丢失或损坏时保留证据并显示待核实；不会通过重新生成来替代丢失图片。

若模型返回后项目存储本身不可写，FWV 无法保证结果跨服务重启保留。界面会以错误提示明确显示“尚未落盘，结果仅在当前服务内存中，请勿关闭服务”，允许磁盘恢复后重试本地保存。进程在收到模型结果后、暂存提交前退出也属于未取得可恢复结果的边界。已经提示“已暂存到磁盘”的结果才有重启恢复保证。

## CLI 与应用接口

CLI 使用相同的 provider、持久任务服务和结果暂存，Key 从上述环境变量读取。参考图选择需要资产、版本、文件名三项同时提供。对同一项目重复相同参数和 `--request-id` 会查询原任务；若已有磁盘暂存结果则只重试本地入库，若结果待核实则保持待核实，不重新调用远端模型。这是 FWV 的本地去重，不依赖服务商提供远端幂等。

CLI 在结果已暂存但资产入库失败时，以非零退出码和 JSON 返回项目内的 `recovery` 路径。只有项目暂存也失败时，才沿用独立系统临时目录作为最后备份；该临时备份应按返回路径手动取回，不会自动扫描并导入。项目与临时目录都不可写时，CLI 明确报告结果未能保存，不能声称重启后可恢复。不要重新调用模型来重试本地写入。

```powershell
node bin/fwv.mjs provider-check
node bin/fwv.mjs generate --project D:/Art/MyGame --prompt-file D:/Art/request.txt --name "治疗药剂" --size 1024x1024
```

Node 接口分别导出为 `fwv/generation/provider` 和 `fwv/generation/jobs`。界面使用受来源和 CSRF 保护的应用命令 `provider.configure`、`provider.check`、`generation.start`、`generation.cancel`、`generation.save`；状态通过 `/api/fwv/provider` 与 `/api/fwv/generation/jobs` 读取。

## 验证边界

本次验证通过本机模拟模型服务检验实际 HTTP JSON、Multipart、鉴权头、异步状态、图片字节及入库导出；没有调用真实收费模型。服务账号权限、实际额度及模型视觉质量需要用户自己的服务配置完成后验证。

接口按 2026-09-07 查阅的官方 [Image generation guide](https://developers.openai.com/api/docs/guides/image-generation) 与 [Images API](https://developers.openai.com/api/reference/resources/images/methods/generate) 实现；后续模型能力变化由服务适配器继续维护。
