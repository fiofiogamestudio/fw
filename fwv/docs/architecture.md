# FWV 架构与范围

FWV（FW Visual，当前产品讨论中称 FWD）是面向素材查看、问题定位、修改候选与验收的美术工作台。素材中心保存可继续编辑的生产过程，并交付可验证的游戏资产。业务内核可以独立使用；FWE 提供编辑界面，FWA 可以通过 CLI/API 调用，FWC 只消费交付资源。FWV 不运行通用 Agent 编排，不实现第二套文件编辑器，不修改游戏玩法。

## 第一版

- 素材中心：确切原版、选区/对象/动作时刻锚点、问题与保持范围 → 修改候选 → 独立人工评审 → 采用为原素材新版本。生成与外部候选可确定性锁定选区外像素；旧生产流程作为专业工具继续使用。
- 角色生产流程：从已有 Spine 模板分析槽位、骨骼关联、初始绘制顺序和图集部件；将选定部件排列为固定 1024² 模板图，统一调用一次图像编辑，再裁回原图集形成角色候选。持久保存方案、请求意图和候选来源。局部重做沿用选定候选的其余部件。
- 立绘制作骨骼：从确切图片版本创建可校正的多边形分区、关节点和父子关系；本地裁切、打包图集、生成刚性部件骨骼及基础动作候选。生成的 Spine 资产可接入既有换皮流程。
- 生成：角色流程可由本地 Agent 领取，记录理解后使用当前对话的内置生图；也可接用户配置的 GPT Image / 基础 OpenAI Images 兼容接口。两种模式保留真实结果、提示词、模型和来源；API 另存实际返回的用量。
- 图片：导入 PNG/JPEG/WebP，保留原始字节；透明内容裁切、等比缩放、画布与边距规范化、可选按指定颜色去底；修订版本、回选、技术检查、导出。
- Spine：4.2 JSON、文本 Atlas 和 PNG 贴图；素材检查、按原 Atlas 区域替换图片、位置与尺寸调整、真实运行时预览、原格式导出。骨骼、网格权重、动画时间线与 Atlas 布局保留。源结构不适配新形象时需要继续校准。
- 已有骨骼修复：检查真实骨骼层级、局部变换和 mesh 权重；修改 setup pose 的指定字段、已有更早父级，或独立 weighted mesh 的单顶点既有 influence。产物仍是待人工评审候选；不修改动画时间线或贴图。
- 界面：通过 FWE 的 Source、`.fwe` 类型模型和 Workbench Layout 扩展承载中文资产工作台；同一应用命令服务于界面与 CLI。

## 后续范围

1. 项目风格规范、批量图片流程与更丰富的候选比较；增加服务适配器与服务账单对接。当前只保存实际返回的用量，不估算费用。
2. UI 九宫格、图标套件、序列帧与 Tile 校验。
3. Spine 网格拓扑/新绑定制作、共享网格/约束与时间线编辑、更多经过验证的版本适配、目标 Godot 导入验收。
4. 根据真实需求接入 3D 模型、材质和动作工具。

任意画风的自动语义拆件、遮挡补全、加权网格绑定、AI 动作生成、3D、Godot/Unity 运行时验收仍未实现。立绘流程中的自动绑定限于已标注部件与关节点，基础动作来自规则预设。运行时资源包也不等于可编辑的 `.spine` 工程。

## 分层

```text
src/core       项目、资产版本、文件完整性、检查、导出
src/image      图片加工
src/generation 服务凭据、Images API、异步任务与产物入库
src/workflows  素材问题、候选、评审、采用；模板生产方案与生成恢复
src/spine      Spine 格式/权重检查、区域处理、已有骨骼局部修复
src/rig        立绘拆件草稿、局部绑定与基础动作、Spine 候选构建
src/editor     FWE 外层适配、命令 HTTP API、专业视图
bin            命令行入口
```

2D 与未来 3D 共用版本、产物、加工与验收合同；各自维护专业数据。图像处理可以同时被两边使用。内核不能导入 FWE 或 FWA；FWE 不导入 FWV。编辑器按显式路径使用现有 FWE，不内嵌副本。Spine 播放器是可选依赖，普通图片处理无需它。

## 数据权威

`fwv.project.json` 是项目索引，`assets/<asset>/<revision>/` 保存不可覆盖的版本文件，`exports/<package>/` 保存交付副本与清单。项目放在宿主的美术源目录或独立资产目录；源文件与索引可一同纳入 Git，大文件由宿主决定是否使用 LFS。临时项目与浏览器验收证据不进入框架源码。

一个版本包含父版本、加工配方、专业元数据、文件名/类型/长度/SHA-256，以及技术验收记录。变更先形成新版本，再选择使用版本。重新选择旧版本不会删除后续版本。原始导入文件、过程版本、导出包彼此分离。

项目索引的 `changes` 数组保存素材问题闭环，旧项目缺少时视为空。问题固定源版、定位条件和要求；候选固定实际版本及文件身份，人工评审单独追加。采用前重新检查候选与源版，已接受候选复制成原素材新版本并切选，遇到外部版本变化拒绝覆盖。专业域通过 `ArtChanges.addPreparedCandidate` 在同一写锁中返回产物并挂候选，不各自创建评审或采用真值。详细命令、选区合成、生成恢复和导出追溯见[素材修改合同](art-changes.md)，已有骨骼的有界修复见[Spine 修复合同](spine-repair.md)。

生成型服务保留实际输出，不承诺通过相同提示词复现相同像素。参考图编辑同时保存输入图片字节和来源版本。确定性的加工使用固定工具版本，并保留参数与输入版本。

生成任务在派发前写入 `.fwv/generation/<job-id>/job.json`；返回图片、参考图及固定来源信息先按长度和哈希暂存，以 `result.json` 作为完成标记，然后登记资产。同一请求编号跨进程检查参数身份，不能重新派发。资产的 `importReceipt` 在项目索引事务内记录任务、内容指纹及首次入库版本，使提交成功但响应丢失后的重试返回同一资产，且不改变用户后来选择的版本。入库与成功状态均记录后清理暂存图片，保留请求记录。

重启后通过检查的暂存结果可继续本地保存，不调用模型；损坏结果保留并提示恢复失败。派发后尚无可恢复结果的中断显示未知，网络超时、取消等待或不可解析的成功响应也不自动重复请求。若磁盘暂存失败，已有返回字节留在当前进程内，界面明确表示不能保证重启恢复。详见[生成服务说明](generation.md)。

图片版本的 `parentId` 表示编辑历史，`metadata.processing.inputRevisionId` 表示实际加工输入。`mode=revise` 沿用该输入重算配方，旧加工版本缺少此字段时使用原父版本；`mode=append` 以当前像素继续加工。界面默认修订已有配方，追加模式提供中性参数；CLI/API 不指定模式时保持追加行为。缩放方式的配置枚举与处理层一致：contain、cover、fill。

角色流程在这层之上持久保存 `kind=reskin` 的方案版本。生成请求在模型调用之前登记，同一流程的请求编号跨服务重启也不重新派发；重启后未确认的远端执行显示未知，已入库部件图可继续本地装配。每次装配形成新的 Spine 资产，模板保持原样。并发编辑通过索引锁与预期版本检查拒绝覆盖。详见[角色换皮流程](reskin-workflow.md)。

本地 Agent 路径不创建 API GenerationJobs。领取凭据、理解、单次派发意图和输出身份属于流程持久状态；图像/候选与流程关联在同一次索引事务保存，避免并发重复产物。执行仍由当前对话承担，FWV 不运行或唤醒模型。显式取消后拒绝晚到结果复活任务，未知执行不自动重发。详见[本地 Agent 合同](local-agent.md)。

立绘草稿保存为 `kind=rig`，每版保留原图参考与相同的文档/元数据。多边形、关节点和父子关系均为源图像素坐标，视图通过应用函数保存，不能直接修改 Spine 数据或索引。构建将指定草稿转换为新的 `kind=spine` 候选，保留草稿来源以便继续修改与重建。详见[立绘骨骼流程](rig-workflow.md)。

## FWE 编辑合同

`src/editor/app/authoring.fwe` 声明五个类型化集合：换皮、拆件、图片配方、生图、Spine 参数。可编辑的拆件部件、关节点和动作有明确类型；画布像素几何及生产验证仍属于 FWV。`fwe.app.json` 通过 FWE 的 `extends` 配置继承编译模型，声明工具栏动作和界面配置文件，不在服务启动代码中拼装表现定义。

主界面的七份 `*.ui.json` 声明普通布局、表单、列表、按钮、文案和运行状态绑定。FWE `ui.createSurface` 复用原生 Inspector 控件和框架样式，`schemaPath` 直接读取编译模型的类型、枚举、范围和文本长度；`surface.update` 原地更新配置绑定，保持输入焦点。FWV 不维护另一套 DOM 控件工厂或普通 CSS。生图质量与尺寸的任务校验复用服务适配器已有能力，避免表单能保存、执行却拒绝同一参数。

`registerWorkbenchLayout('fwv-workbench')` 只适配业务动作、数据、FWE 生命周期和专业画布。FWE 侧栏是唯一主导航，已移除内部重复标签、装饰步骤卡片及“参数草稿”第二入口。换皮、拆件与 Spine 的播放条共用 `preview.ui.json`。FWV 自定义渲染仅保留 SVG 拆件几何/指针交互以及 Spine WebGL 绘制；专业画布的周边控件也由配置生成。

工作页采用渐进展开：主预览和当前必要输入常驻，高级参数、部件要求、历史和技术检查由原生 `details` 承载。FWE 的 `workspace` 预设按容器宽度分配主区与约 340px 参数栏，`stage`、`thumbnail` 控制专业预览与缩略图尺寸；FWV 只选择配置预设。状态需要下一步操作时才自动展开对应入口，轮询不会反复覆盖用户手动折叠。模型服务未配置时展开设置，已配置后默认收起。

面板通过公开 context 的 `pushHistory`、`markDirty` 更新当前模型，FWE 顶栏与快捷键统一负责撤销、重做、保存和离开页面提示。拆件拖动在一次手势结束时提交一条历史；模型被撤销、重做或重新载入时，专业面板重新读取模型。切换面板销毁播放与轮询资源，草稿留在 FWE 模型中。密码和文件选择属于临时输入，FWE 控件不会将其自动写入文档。

`fwv-authoring` Source 只读写固定的虚拟资源 `authoring.json`，对应项目 `.fwv/editor-drafts.json`。首次保存使用 `createOnly`，通过排他硬链接发布已同步的临时文件，外部工具抢先创建也不会被覆盖；后续保存使用源文件原始字节哈希作不透明版本标识，在项目写锁内执行检查与原子替换。旧窗口遇到外部修改收到 409，FWE 保留未保存参数，不覆盖外部文件。读取损坏文件或不匹配的项目身份会明确失败，不用空文档静默替代。

Source 验证集合、标识、参数类型与可恢复的拆件结构，允许未完成多边形等编辑中间态；生产几何校验留给显式保存/构建命令。该文件不包含 API Key，不改动 `fwv.project.json`。资产索引仍由单独的只读 `fwv-project` Source 提供。

因此 **Ctrl+S 保存编辑参数，不生产资产**。保存换皮要求、保存拆件版本、调用模型、构建骨骼、选择交付版本和导出都有独立应用命令。FWE 编辑历史不能撤回模型执行，也不删除不可变资产版本；需要回选旧资产时使用版本功能。CLI 继续操作资产应用层，编辑器草稿不是资产索引的替代品。

Spine 草稿按资产、版本和部件记录替换图身份及变换，旧单部件草稿兼容迁移。受保护的只读 `spine.preview` 命令复用实际替换算法生成临时图集纹理，播放器保持时间和动作；预览不写项目，过期异步响应不能覆盖新输入。历史拆件只读，通过显式创建副本继续制作；当前版本保存仍检查并发修改，副本保留原始来源。

## 验收语义

技术检查针对可读取性、尺寸、透明内容、哈希和资源完整性。Spine 浏览器播放用于人工检查动画，不能被当作目标游戏运行成功。自动检查通过不会自动写成人工验收通过。导出包校验及回读也不能代替 Godot/Unity 场景验收。

## 本地运行边界

编辑器固定一个项目，仅监听 loopback。资产写入通过应用命令，FWE 通用保存仅开放固定的参数草稿资源，不开放任意路径读写或资产 CRUD。源资源只按资产/版本/已登记文件名读取。写入遵循项目锁与原子更新，损坏资源阻止导出。这里是可信本机工作台，不是互联网多租户服务。

## 家族装配

当前代码位于顶层工作台的 `fwv/` 独立包中，开发入口是 `fw visual` 或 `fwv editor`。正式发布需要建立实际独立仓库、测试后提交并登记可获取的 gitlink；未完成该步骤前，不伪造远端地址、提交 SHA 或 `fw deps install fwv` 支持。
