# 模板驱动角色换皮

输入是一套可用的 Spine 4.2 骨骼模板，以及希望制作的角色设定。输出是保持该模板骨骼、权重、动作和图集布局的角色候选。FWV 负责安排部件、发起统一生成、切图装配、保留版本以及局部修正。

## 操作流程

1. 在「2D 骨骼换皮」导入自己的 JSON、Atlas 和 PNG，或使用示例的六部件猫咪模板。
2. 在「角色换皮流程」选择模板和确切版本，填写角色设定、共同画风与配色。选择 1 到 16 个区域，补充部件要求，例如胸甲、护臂、靴子的材质和颜色。
3. 创建方案。此步骤不调用模型，会保存部件布局图和生产要求。检查布局、朝向与选择范围。
4. 选择本地 Agent 或 API。本地模式建立任务后交给当前 Codex 对话，由 Agent 查看参考、记录分析并调用内置生图；API 模式配置服务后使用一次 Images 编辑请求。所选部件一起进入一张 1024×1024 参考图，提示词记录位置、尺寸、槽位和要求。[本地任务操作与恢复](local-agent.md)。
5. 模型返回后，FWV 按固定区域裁出部件，恢复原始画布尺寸，处理图集旋转、裁边和 PMA，生成独立 Spine 角色候选。模型必须遵循原布局；FWV 不猜测漂移后部件的新位置。
6. 在真实 Spine 运行时检查动作。问题部件可本地调整位置、大小、旋转和翻转，然后重装；需要重新绘制时，只勾选对应部件并重新生成。局部生成以当前角色候选为基础，其他部件原样保留。
7. 选择要使用的候选并导出，再到实际游戏里验收。

工作台保留通用「AI 生图」与图片加工页，供单张素材需求使用；角色流程自动处理这些底层步骤。

## 范围与取舍

单张部件图让各部件在同一次模型调用中共享角色设定和风格。第一次生成全部选定部件，之后可以按小批次修正。当前每批最多 16 个部件；细长或较大部件缩入模板图时会提示细节损失。大图集可以分批制作，后续方案以选定候选为模板。

默认启用原始透明轮廓遮罩：把模型生成的 alpha 与原部件 alpha 相乘，再应用局部变换。这适合复用现有体型、关节和网格，不能靠提示词增加新肢体或扩大原始轮廓。关闭遮罩后，模型背景也会进入贴图，仍受原图集裁边限制。体型、动作或网格不适配时需要独立编辑骨骼与绑定。

换皮保持既有骨骼与动作；没有模板时可通过独立的[立绘拆件与骨骼流程](rig-workflow.md)手工校正标注并生成规则骨骼与动作。本地 Agent 的语义分析可补充部件说明，但不等同于自动像素分割。统一提示词和布局约束不能保证模型始终遵从，真实输出必须检查。

## 技术检查

- 调用模型前：校验模板版本、已登记文件哈希、部件数量和尺寸，拒绝选中的重叠区域、九宫格区域及不支持的 Spine 数据。
- 模型结果：必须是无 EXIF 旋转的 1024×1024 有效图片；不能自动缩放错误画布来掩盖布局变化。
- 装配：对每个部件记录原始、生成、遮罩后和最终的非透明像素数量；原本可见的部件完全消失时拒绝生成候选，最终覆盖不足原部件 50% 时提示检查。
- 导出：验证登记资源的长度与哈希，保留骨骼 JSON 和 Atlas 原始字节。

像素统计采用 alpha≥1。覆盖率衡量是否缺失，不评价画面内容是否正确，也不证明关节、遮挡或动画视觉通过。全部动作及目标游戏内效果仍需人工检查。

## 数据与恢复

方案以普通资产 `kind=reskin` 保存，文件为 `workflow.json`，索引元数据为 `metadata.reskin`。每次改要求或推进生成状态形成新版本。骨骼模板、原始部件图、生成部件图和装配候选都是已登记资产，通过资产 ID 与不可变版本 ID 关联。

每次生成记录原始模板、实际装配基础、所选部件、实际提示词、模型配置与任务编号。候选保留生成图文件及布局、来源、变换与部件检查。局部重新装配保留新的候选资产和装配记录，不重复调用模型。

生成意图先持久化再派发。同一方案内的 `requestId` 不会因刷新、重复提交或重启而再次调用模型。不同内容应使用新的请求编号。服务重启后未完成的请求不会自动继续付费；无法确认的远端结果显示 `unknown`。已保存生成图的记录可继续本地装配。

模型返回后先将完整图片、参考图和生成来源写入项目的 `.fwv/generation` 暂存区，再登记素材。若入库失败，重启后仍显示可恢复，点击「保存并装配角色」沿用原生成任务继续完成。关联会核对请求编号、提示词、模型配置、确切参考版本及尺寸/质量/背景合同，不会把另一任务的结果接入本方案。

若磁盘暂存本身失败，界面明确提示结果仍仅在当前服务内存中；若暂存文件损坏，保留文件并显示待核实，禁止自动重新调用模型。已登记图片和装配候选均使用持久回执防止失败重试或响应丢失造成重复产物；相同校准参数重复装配返回已有候选，改变参数才产生新候选。

## 应用接口

Node 接口：`fwv/workflows/reskin` 的 `ReskinWorkflows({project,generationJobs})`。

| 方法/HTTP 命令 | 用途 |
| --- | --- |
| `create` / `reskin.create` | 创建模板与角色方案，不调用模型 |
| `update` / `reskin.update` | 修改设定、风格和部件说明 |
| `generate` / `reskin.generate` | 登记请求，统一编辑部件图并自动装配 |
| `assemble` / `reskin.assemble` | 从确切任务恢复暂存生成图并装配，或用已保存图重新校准 |
| `select` / `reskin.select` | 选定后续局部重做的基础候选 |
| `cancel` / `reskin.cancel` | 取消本地等待，保留远端不确定结果 |

查询通过 `GET /api/fwv/reskin/workflows` 和 `/api/fwv/reskin/template`。所有写命令沿用 FWE 本机来源及 CSRF 校验。

## 验证

```powershell
npm.cmd test
node tools/test-reskin-browser.mjs
```

自动验证使用真实 Spine 数据、原始像素和测试自建的本机模型接口，检查完整与局部替换、动作预览、持久恢复、请求数量和导出资源。模拟服务生成的配色结果仅用来验证装配流程；真实模型的视觉质量与布局遵从性尚需使用用户自己的服务验证。
