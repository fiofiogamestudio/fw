# 3D 模型、贴图与绑定

从素材中心导入 GLB，点击“3D 模型与绑定”。空项目也有“导入 / 检查 GLB 模型”入口。项目继续使用既有 `fwv.project.json` 与不可变版本文件，模型类型为 `model3d`，不是另建一套资产库。

## 查看与定位

- 默认用一个大视口显示当前模型；有修改结果后再显示原版和修改后两个视口，同步相机、动作和时间。“显示选项”中可打开骨骼及线框。外部结果的动画按名称匹配，顺序变化不会选错；名称缺失或不唯一时停止该动作对比并提示。
- 只需填写“想怎么改”，标题自动生成；保持条件可选。“准备修改说明”固定源版本、动作时间和当前相机，输出可交给 AI / 外部工具的完整说明。修改后的 GLB 可在当前页面直接导入为候选。
- “手动修复”中按需打开骨骼、权重或贴图工具。操作会沿用当前修改要求；未建请求时会先记录要求。模型专业页尚未记录的参数仍只是本次页面内输入。
- 有结果时，预览上方提供“用这版”和“继续修改”。“用这版”依次记录人工验收并执行技术检查与采用；被驳回、已采用、源版本冲突时不能误用。若其他窗口已修改评审或采用状态，旧页面会提示冲突。失败后读取真实状态，不自动切换其他结果。
- “继续修改”保留要求；采用后从当前新版本继续，未采用时仍以左侧原版生成其他候选。历史版本、单独评审及模型原始诊断收在“版本与修改记录”中。

## 生成修复候选

骨骼局部修复支持已有 TRS 骨骼的位置、四元数和缩放。它调整基础姿态，保留逆绑定矩阵和原动画时间线；这不等同于重新生成蒙皮绑定。动画对应通道可能覆盖基础姿态，评审时应同时查看基础姿态与指定动作。矩阵节点、重挂父级、重建骨架及自动重绑暂未提供。

权重修复支持读取指定网格 / Primitive / 顶点的 `JOINTS_0` 和 `WEIGHTS_0`，修改四个既有影响的数值并归一化。不会隐式换绑骨骼。只替换目标 Primitive 的权重 accessor，其他顶点数值、原二进制数据及其他引用者保留；共享这一网格的实例都会使用修改。Sparse 和超过四个影响的网格暂不可编辑。

内嵌贴图可提取成普通图片素材，进入现有的圈选、AI 重绘、候选评审流程。完成后回到 3D 页选择图片及确切版本，生成贴图替换候选。原材质参数、UV、几何体、骨骼和动画继续保留。它替换指定图片，因此引用该图片的材质都会看到修改。

所有修复先生成待评审候选。技术检查与人工接受分别记录；“用这版”成功后才把选定结果加入原素材的新版本。原版、其他候选和评审记录保留。候选文件被改变、基线已发生冲突或技术检查失败时不能采用。

若源模型的唯一技术问题是已识别的可修复权重错误，可以建立修复请求并保留失败诊断；直接导出仍被阻止。修复候选、采用和导出必须通过完整技术检查。

## 格式与验证范围

首版支持 glTF 2.0 GLB：单个内嵌 buffer、PNG/JPEG 内嵌贴图、单文件最多 20 MiB。支持基础 glTF、`KHR_materials_unlit` 和 `KHR_texture_transform`；外部文件/URL、压缩网格、其他扩展、FBX、Blend、OBJ 尚未适配。

模型使用本地固定版本 Three.js 渲染，结构与数值通过 Khronos 官方 glTF Validator 检查，贴图还需可实际解码。规范依据 [glTF 2.0](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)，运行时实现参见 [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)。技术通过不代表目标游戏引擎、动作观感或美术质量已验收。

诊断达到 100 条而被验证器截断时，检查视为未完成；应先清理未使用对象或分拆素材后重试，不能把尚未扫描的数据算作通过。

## 验证入口

本地 AI 可直接使用相同应用操作，不必操作浏览器：

```powershell
node bin/fwv.mjs model-import --project D:/Art/MyGame --file D:/Art/source.glb
node bin/fwv.mjs model-inspect --project D:/Art/MyGame --asset <asset-id> --revision <revision-id>
node bin/fwv.mjs model --project D:/Art/MyGame --file D:/Art/repair.json
```

`repair.json` 使用与界面一致的 `type` 与 `payload`，例如 `model.candidate.repair`，包含已建立的 `changeId`、可重试的 `requestId` 及骨骼/权重/贴图修改。它创建候选，不自动替用户评审。

在 `fwv/` 目录运行：

```powershell
node --test test/model.test.mjs
node tools/test-model-browser.mjs
```

浏览器用隔离工程与 Chrome 配置实际上传模型，检查材质、骨骼、动作时间、修复候选、贴图提取、人工采用和重开历史。报告与截图保留在 `.local/reports/model-browser/`。测试使用本地生成的蒙皮模型，没有调用在线模型或修改用户的美术工程。
