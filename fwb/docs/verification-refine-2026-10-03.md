# FWB 本地构建与交付流程打磨

范围为 FWB 0.1.0 当前工作区（FW 基础提交 `02126db`，包含此前未提交的平台分类、Web 压缩和微信转换编排）。本轮按配置可操作性、构建隔离、产物可信度、回归证据四项复核，没有变更框架 Godot 基线，也没有提交或发布。

## 查实并修复

- 工程和本机环境草稿此前不会阻止依赖操作，界面显示新值、后端使用旧值。现在持续显示未保存提示，检查、构建、补预设等操作先要求保存或重读；临时验收表单不误触发这个限制。
- 共享资源准备此前只有选择入口。工程页现在可编辑共享 Web 脚本，平台页可覆盖或清空，并立即显示真正生效的脚本。其他流水线和目标配置保留。
- 相对 SDK 路径重复浏览此前会被后端拒绝。现在按工程根定位，选择工程内 SDK 或脚本后写回相对路径。
- init 的小游戏固定预设名与转换路线默认值冲突。现在使用统一的路线默认值，显式用户预设仍优先；未配置目标不再被视作已启用。
- 项目内模板此前可能指向源工程的文件。现在预检确认其进入快照，导出预设和工具链指纹均使用同一冻结副本，外部安装模板保持原行为。
- Godot 返回零退出码但在日志早期报告错误时，超过 128 KiB 的后续输出此前可能掩盖错误。现在按完整 stdout/stderr 输出流记录错误，覆盖跨块和颜色转义，保留有界内存与滚动输出。
- Web 原始包此前可能接受空启动文件、截断 WASM 或伪 PCK。现在原始与 gzip 路线均检查非空入口、WASM 完整版本头及 PCK v2/v3/v4 固定前缀与目录边界；这不等于完整解析所有资源或执行引擎。
- ZIP 下载此前可能绕过最近失败的包检查及预算。现在下载前重新验证完整产物，再对实际归档字节核对身份。
- 预览此前只在启动时校验。现在逐请求检查并返回同一个文件 Buffer；启动后替换、删除或改写文件会被阻断，不以 mtime 缓存代替内容身份。
- 构建内预检失败此前只显示总错误，页面仍称尚未检查。现在失败任务保留匹配目标和配置的预检结果；预检通过后的导出失败依然明确显示为构建失败。

- `npm test`：188/188，通过，零跳过；日志 `.local/refine-tests-20261003.log`。`git diff --check -- fwb` 通过。
- 真实工作台完成共享资源脚本填写、未保存构建阻断、保存与生效来源展示；平台覆盖和重复路径浏览另有直接调用实际 UI、状态层及配置保存的回归。
- 最终界面用缺失预设触发失败构建 `build_1790981004688_40ea09746c8143d289d399ef7c6fa17e`，确认显示具体受阻原因、目标标记缺少条件、构建按钮禁用；随后恢复原预设，保存配置哈希回到构建前值。

## 余项与停止条件

本轮已查实的配置、隔离、检查和交付缺口已修复并完成相称验证。微信仍需要匹配当前游戏引擎的已验证 SDK 和真机证据；TapTap 客户端、Poki Inspector、Android 设备与签名、Mac/iOS 及实际上传分别需要对应环境。本轮没有完成这些平台验收，也没有把自动化测试或浏览器示例通过升级为全部渠道可发布。

交接：FWB 0.1.0 本地流程｜配置、隔离、产物、回归四维｜本地证据可信度高，平台完成度仍有缺口｜188 项测试、真实 Web 与模板回归、浏览器交互及存档通过｜在平台 SDK、设备及账户验收边界停止。
